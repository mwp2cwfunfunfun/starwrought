# STARWROUGHT

A classless d20 tabletop roleplaying game, and the tools that build it.

Characters are built from Talent Constellations rather than classes. Attributes emerge from where
you invest rather than being bought, proficiency comes from what you have actually done, and the
table's critical moments Flare the Constellations that grow.

## Installing the Foundry VTT system

In Foundry, go to **Setup → Game Systems → Install System**, and paste this manifest URL:

```
https://github.com/mwp2cwfunfunfun/starwrought/releases/latest/download/system.json
```

Foundry 13 or later. The system sets its own grid: one foot per square, with diagonals measured
exactly, which needs a restart to take effect after installing.

See [the system's FEATURES.md](foundry/starwrought/FEATURES.md) for what it actually does, and
[its CHANGELOG.md](foundry/starwrought/CHANGELOG.md) for what changed when.

## What is in here

| Path | What it is |
|---|---|
| `Starwrought_Players_Handbook_v*.docx` | The rules, hand-authored. The highest-numbered file is authoritative |
| `data/*.xlsx` | All game content: one workbook per category, one sheet per Constellation |
| `foundry/starwrought/` | The Foundry VTT system |
| `assets/` | The pipeline that turns the spreadsheets into everything else |
| `Starwrought_App.html` | A standalone character builder, no server required |
| `Starwrought_Constellation_Compendium.docx` | Every Constellation, generated from the data |

The spreadsheets are the source for everything a machine reads; the handbook is the source for the
rules themselves. When the two disagree, the handbook wins and the sheets need a pass.

## Building

Everything is generated by one command, which also checks that nothing downstream has fallen behind
the handbook:

```
node assets/build_all.mjs
```

It needs Node, plus `openpyxl`, `matplotlib`, `reportlab` and `python-docx` for the Python steps.
`--check` runs only the drift check, and `--skip-slow` leaves out the plates, the character sheets
and the compendium.

To package the Foundry system for a server of your own:

```
node assets/package_system.mjs
```

That writes `dist/starwrought.zip`, which can be unpacked straight into a Foundry server's
`Data/systems/starwrought/`. Pushing a `v*` tag builds the same archive in CI and publishes it as a
release.

The compiled compendium packs under `foundry/starwrought/packs/` are not committed: they are
LevelDB databases that a running Foundry rewrites. Their JSON sources in `packs/_source` are, and
`node assets/build_foundry.mjs` compiles them, which is also what the release workflow does on a
fresh checkout.
